## 7. 审计结论与后续建议

1. 组织主数据存在简称到 Code 的多值问题。秦皇岛已实证命中 4 个 Code；在没有组织层级/公司类型约束前，不应自动选第一条。
2. 参数表 62 条与公司简称 85 家公司基线不一致，空值率必须在 Code 对齐后再用于计算，尤其折标系数的 0 值与 NULL 需要区分。
3. 实库当前数据只到 2026-08-31；2026 下半年表已经存在但尚未覆盖完整半年，2027/2028 分表为空。查询层需要按 Cutoff Date 做未来日期保护。
4. 公式资产不是 46 项全量闭环：精确名称命中且有正文 24 项，另有 1 项公式行正文为空，21 项精确名称缺失。应先收敛名称、单位、入厂/入炉口径，再补公式 SQL 和测试样本。

## 8. 查询安全与可复核口径

本次使用的查询类型包括：

- `information_schema.tables` / `information_schema.columns`：表清单和结构；半年表使用严格正则 `^CGXTAPPMISDate_[0-9]{4}_[0-9]{2}$`，排除了 `_bak` 等非标准表。
- `COUNT(*)`、`MIN("ZBRQ")`、`MAX("ZBRQ")`、`COUNT(DISTINCT ...)`：真实行数、日期范围和覆盖数。
- 核心表及每张半年表的 LIMIT 3 样本查询：用于字段和内容核验。
- 组织匹配：对实库 `Name_CHS` 做短名键包含匹配；报告只展示证据和差异，不执行任何回写。
