# 流程助手功能说明

更新时间：2026-09-02

> 复核备注：本次独立浏览器已复现采购请示单动作卡片和一次 IGIX_ACTION_SEND。真实表单是否打开、门户是否回执、权限和审计是否落库，仍需在 iGIX iframe 环境确认。当前字段预填开关为 false。

## 1. 功能定位

流程助手是环宝 AI 智能助手中的“业务流程入口助手”，用于帮助用户定位、打开 iGIX 表单、菜单、台账和看板入口。

当前阶段定位为“企业级试点上线版”：首版只支持打开已验证的 iGIX 表单 / 菜单入口，不做字段预填，不自动填表，不自动提交。

- 不接 Dify candidates。
- 不发送 `fields`。
- 不自动提交表单。
- 不做真实权限过滤。
- 不绕过 iGIX 权限体系。
- 不把流程助手做成纯文本问答。

## 2.1 当前页面实际行为

- 输入“打开采购请示单”：识别为采购请示单，展示可执行卡片；点击后发送打开动作。
- 输入“通用性备案表”：识别为通用性备案表，但因状态为 `pending`，卡片显示“待实测，暂未开放”，不发送动作。
- 输入“合同评审”“合同评审流程”等未配置事项：不展示假卡片，提示补充具体表单或流程名称。
- 输入“你都可以打开什么菜单”：按流程清单规则返回当前配置入口；真实可办理权限仍以 iGIX 为准。
- 流程卡片和普通助手回复继续支持复制、导出 Markdown、导出 Word。

## 3. 当前动作协议

流程助手点击动作按钮后，前端向父页面发送：

```js
window.parent.postMessage({
  type: 'IGIX_AI_ACTION',
  payload: {
    action: 'open_form',
    formCode: 'CGQSD',
    funcId: '9744034a-7fcc-4510-97fa-f563aecd26e6',
    actionId: '...'
  }
}, portalOrigin)
```

### payload 字段说明

| 字段 | 是否必填 | 说明 |
|---|---|---|
| `action` | 是 | 当前支持 `open_form`、`open_menu`。 |
| `formCode` | 是 | iGIX 表单、菜单、台账或看板编码。 |
| `funcId` | 是 | iGIX / 门户功能 ID。 |
| `fields` | 否 | 试点上线版不发送该字段，保留为后续扩展协议。 |
| `actionId` | 是 | 前端发送前自动注入的动作唯一标识。 |

### action 映射规则

| 配置动作类型 | 实际发送 action | 说明 |
|---|---|---|
| `open_form` | `open_form` | 打开表单，不携带字段。 |
| `open_form_prefill` | `open_form` | 试点上线版只打开表单，不携带 `fields`。 |
| `open_menu` | `open_menu` | 打开菜单、台账或看板，不携带字段。 |
| `open_related` | 不发送 | 联查类入口，暂未接入直接打开协议。 |

## 4. 配置来源

流程助手入口配置主要来自：

- `src/config/workflowActions.js`
- `docs/表单菜单映射清单.md`

维护要求：

1. 文档和前端配置必须同步。
2. 只有 `status = verified` 且 `formCode` 和 `funcId` 都明确时，才允许配置可执行动作。
3. `open_related` 不允许发送 `IGIX_AI_ACTION`。
4. `status = pending` 的入口只展示“待实测，暂未开放”，不展示执行按钮。
5. `status = unsupported` 的入口只展示“不支持直接打开”，不发送动作。
6. 清单查询必须提示“当前展示的是已配置入口状态，实际可办理权限以 iGIX 权限为准。”

## 9. 关键风险点

| 风险 | 说明 | 当前处理 |
|---|---|---|
| 权限风险 | 前端不知道用户是否有权限办理某入口。 | 只展示已配置入口，实际权限以 iGIX 为准。 |
| postMessage 来源 | actionBridge 当前按显式门户 origin、referrer origin 或开发默认值解析 targetOrigin。 | 生产必须配置明确的 VITE_IGIX_PORTAL_ORIGIN，并由父页面校验 event.source 和 event.origin。 |
| 字段误填 | 字段标签、类型、控件未确认时可能填错。 | 试点上线版关闭字段预填。 |
| 重复动作 | iGIX 多监听器可能重复消费同一消息。 | payload 注入 `actionId`；父页面必须按 `actionId` 幂等去重。 |
| Vue Proxy 克隆失败 | 响应式对象直接 postMessage 会报 `DataCloneError`。 | `actionBridge` 统一清洗 payload。 |
| 联查入口协议不明 | `open_related` 可能不是直接打开表单。 | 当前不执行。 |

## 10. 下一阶段建议

1. 对各 `pending` 入口逐项在 iGIX 环境验证，验证通过后再改为 `verified`。
2. 增加真实权限校验，避免向无权限用户展示可执行入口。
3. 增加操作审计，记录用户、入口、动作、`actionId` 和执行结果。
4. 配置 `postMessage` origin 白名单。
5. 确认 `open_related` 联查类入口协议。
6. 如后续重新启用字段预填，必须单独立项、单独验收，不纳入试点上线首版。
