# 表单菜单映射清单

更新时间：2026-07-22

## 这份文档给谁看

本文档用于维护“流程助手”与 iGIX 表单、菜单、台账入口之间的映射关系。

读法分两类：

- 业务用户：先看“用户能怎么说”和“当前可用能力”。
- 开发维护人员：再看“技术映射明细”和“维护规则”。

## 当前可用能力

| 能力 | 当前状态 | 说明 |
|---|---|---|
| 打开采购请示单 | 已验证 | 可通过流程助手打开采购请示单。 |
| 字段预填 | 已关闭 | 企业级试点上线版不显示预填按钮，不发送 `fields`。 |
| 流程入口清单查询 | 已完成 | 支持查询某模块有哪些流程、当前已配置哪些入口。 |
| 按模块展示入口 | 已完成 | 支持采购模块、运维模块、科技模块、综合模块分组展示。 |
| 打开台账 / 看板 / 菜单 | 待实测 | 已有真实 `formCode` 和 `funcId`，但试点首版不开放执行按钮。 |
| 打开其他表单 | 待实测 | 待 iGIX 门户环境逐项验证后再开放。 |
| 联查类入口 | 暂不支持 | 需要后续确认联查入口协议，当前不发送执行动作。 |
| 入口状态治理 | 已完成 | 只有 `verified` 且 `formCode/funcId` 完整的入口展示执行按钮。 |
| payload 清洗 | 已完成 | 动作统一经过 `actionBridge` 清洗，避免 Vue Proxy 导致 `DataCloneError`。 |

当前页面实测表现：采购请示单展示“打开采购请示单”按钮；通用性备案表可被识别但显示“待实测，暂未开放”；合同评审未配置，不会生成可执行卡片。

## 状态说明

| 状态 | 代码值 | 含义 | 是否允许发送动作 |
|---|---|---|---|
| 已开放 | `verified` | 已在当前项目中验证过基本打开能力 | 是 |
| 待实测 | `pending` | 已有真实映射，但还需要在门户环境逐项验证 | 否 |
| 暂不支持 | `unsupported` | 当前协议或入口类型不满足直接打开条件 | 否 |

## 动作类型说明

| 动作类型 | 含义 | 前端发送 action | 是否允许 fields |
|---|---|---|---|
| `open_form` | 打开表单 | `open_form` | 否 |
| `open_form_prefill` | 打开表单，理论上可携带预填字段 | `open_form` | 试点上线版不允许 |
| `open_menu` | 打开菜单、台账或看板 | `open_menu` | 否 |
| `open_related` | 联查类入口 | 不发送 | 否 |

## 字段预填策略

企业级试点上线版关闭字段预填：

- 不显示“帮我预填表单”按钮。
- 点击任何流程动作都不发送 `fields`。
- 采购请示单也只执行 `open_form`。
- 不自动提交表单。
- 用户信息仅用于页面欢迎语，不用于字段预填。

## 维护规则

新增或修改映射时，按下面规则处理：

1. 只有 `status = verified` 且 `formCode` 和 `funcId` 都明确时，才允许配置可执行动作。
2. `open_menu` 只打开菜单、台账或看板，不携带 `fields`。
3. `open_form` 只打开表单，不携带 `fields`。
4. `open_form_prefill` 在试点上线版只打开表单，不携带 `fields`。
5. `open_related` 不发送 `IGIX_AI_ACTION`，只提示“该事项属于联查类入口，暂未接入直接打开协议”。
6. `pending` 入口展示“待实测，暂未开放”，不展示执行按钮。
7. `unsupported` 入口展示“不支持直接打开”，不展示执行按钮。
8. 文档更新后，需要同步检查 `src/config/workflowActions.js`。
9. 前端配置更新后，需要执行 `npm run build`。
10. 未配置可执行动作的事项不得展示假按钮。
11. 用户信息只用于欢迎语，不用于字段预填。

## 动作协议摘要

所有可执行动作统一通过 `actionBridge` 发送：

```js
{
  type: 'IGIX_AI_ACTION',
  payload: {
    action: 'open_form',
    formCode: 'CGQSD',
    funcId: '9744034a-7fcc-4510-97fa-f563aecd26e6',
    actionId: '...'
  }
}
```

说明：

- `payload.action` 当前只发送 `open_form` 或 `open_menu`。
- 试点上线版不发送 `payload.fields`。
- `payload.actionId` 由前端发送前自动注入。
- iGIX 父页面应按 `payload.actionId` 幂等消费，避免多个 listener 重复打开表单。
- payload 发送前会清洗 Vue Proxy / ref / reactive，避免 `postMessage` 克隆失败。
- 开发环境日志会打印 `actionId`、`action`、`formCode`、`funcId`、`status`、`hasFields`、`sentAt`。

## 上线风险

- 权限校验：打开表单、菜单、台账前必须由门户 / iGIX / 后端校验权限。
- postMessage origin 白名单：生产环境不得长期使用 `*`，应限制父页面 origin。
- 操作审计：打开表单、菜单、预填字段等动作应记录审计日志。
- 字段预填关闭：试点上线版不发送 `fields`，不自动填表，不自动提交。
- 联查类入口需单独确认协议：`open_related` 入口暂不直接执行。
