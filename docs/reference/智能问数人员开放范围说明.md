# 智能问数人员开放范围说明

更新时间：2026-09-16

## 当前权限结论

当前代码和文档目标是由 AI Gateway 按可信门户签名身份和服务端 ai_data_query_user 授权表控制，不再把前端姓名静态名单当成生产安全边界。前端只请求 /api/ai/data-query/access 获取界面状态，查询时再请求 /api/ai/data-query/chat。

生产默认使用 DATA_QUERY_IDENTITY_MODE=SIGNED_HEADER。Gateway 校验 X-Portal-Identity、时间戳和 HMAC 签名，再按 tenantId + userId 查询启用状态、组织范围、指标范围、集团排名和全组织权限。BODY_TRIAL 只有显式配置才允许，不能作为生产方案。

## 全员开放模式（open-to-all）

自 2026-09-16 起支持关闭授权表校验、对全部登录门户用户开放：在 Gateway 环境变量设置 `DATA_QUERY_ACCESS_OPEN_TO_ALL=true`（对应配置项 `data-query.access-open-to-all`，默认 `false`）。

开放模式下的行为：

- 身份校验不变：仍要求 SIGNED_HEADER 可信签名身份（userId + userName），未登录或身份缺失依旧拒绝。
- 不再查询 ai_data_query_user 授权表，任何可信身份直接放行，Gateway 日志记录 `DATA_QUERY_ACCESS_OPEN_TO_ALL`。
- 组织范围固定为全组织：Gateway 向 huanbao-dataquery 传 `X-Internal-Allowed-Orgs: *`，问数服务把 `*` 展开为语义包 dim_org_mapping 中的全部组织正式编码后再执行 SQL，SQL 侧 `orgcode IN (:allowedOrgs)` 过滤边界不变。
- 集团排名跟随既有全局开关 `DATA_QUERY_ALLOW_GROUP_RANKING`。

关闭开放只需把该环境变量改回 `false` 并重启 Gateway，授权表内容不受影响。

## 身份桥接

src/utils/igixUser.js 优先读取同源门户 userInfos.get()；跨域 iframe 通过 IGIX_AI_USER_REQUEST / IGIX_AI_USER_RESPONSE 获取用户信息。父页面必须校验 event.source 是当前助手 iframe，并使用 event.origin 回传，不能使用通配 origin。

actionBridge 的门户 origin 优先级是显式 VITE_IGIX_PORTAL_ORIGIN，其次 referrer origin，最后才是历史开发默认值。真实门户仍需验证来源白名单和签名字段是否一致。

## 当前验证

独立浏览器没有当前门户用户。访问线上 data-query/access 时提交空身份，Gateway 返回 401 CURRENT_USER_MISSING；页面因此停在确认开放范围，不会进入 Dify 或 Kingbase 查询。这是预期安全行为。

本次没有连接线上授权表，不能确认生产是否已经为测试用户配置 ai_data_query_user，也不能据此宣称任何真实用户已获授权。

## 管理接口和配置

人员管理接口为 /api/ai/data-query/users，使用 DATA_QUERY_ADMIN_TOKEN；本次未带令牌访问返回 401 invalid admin token。管理 token 不写入前端、文档或 Git。

前端可以保存助手界面状态，不能保存或伪造生产权限。生产权限必须由 Gateway 服务端和数据库共同决定，并在问数审计中记录用户、组织、指标、时间范围、状态和 Dify 标识的脱敏信息。

## 待验收

1. 在真实门户获取可信签名身份。
2. 为测试用户配置最小 ai_data_query_user 授权。
3. 完成 access、有效查询、澄清和会话续问。
4. 核对 Dify 是否消费 auth_context_json 和 DataScope。
5. 核对 Kingbase 真实表字段、SQL 组织过滤、超时、结果上限和审计落库。

旧文档中的静态名单、current_user_name 和前端覆盖判断仅保留为历史方案背景，不是当前生产授权流程。
