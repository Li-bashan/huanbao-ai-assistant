# 问数与公文跨能力协同接口契约规范

## 1. 文档目的与当前状态

本文定义“数据查询结果 -> 公文/材料生成”的未来服务端协同契约，用于后续 Gateway 或 DataQuery 服务端实现和联调。

当前状态：`BACKEND_REQUIRED`。

这不是当前可调用的生产接口，也不代表前端已经具备跨能力协同能力。Task 5 不新增浏览器端串联请求、不在前端拼接 Prompt、不复制或重写问数结果。公开 Gateway/Master 当前没有该接口，后端完成路由、数据锁定、SSE 和一致性校验后，才能进入实现和验收。

## 2. 架构定位

跨能力协同必须明确分离事实层和表达层：

| 能力 | 职责 | 不负责的事情 |
|---|---|---|
| Data Query | Truth：身份授权范围内的数据查询、口径校验、事实快照和来源元数据 | 不负责把查询结果写成公文，不把推测当成事实 |
| Office AI / Master | Presentation：基于已验证只读事实快照组织标题、段落、语气和格式 | 不改动业务数值、不补造指标、不改变统计口径、不执行 SQL |
| Gateway / DataQuery 服务端 | 两阶段编排、权限继承、事实快照冻结、模型调用、数值一致性校验和统一 SSE | 不接受浏览器提交的数值作为权威事实 |
| 前端 | 发起一次协同请求、消费一条聚合 SSE 流、展示阶段和结果 | 不分别调用两个能力、不拼接事实 Prompt、不在浏览器做事实编排 |

核心原则：问数负责事实，公文负责表达。表达层可以改变语言，不可以改变事实。

## 3. 协同铁律

### 3.1 必须由服务端完成两阶段调用

Gateway 或 DataQuery 服务端必须在同一条受控服务链路内完成：

1. 使用签名身份和服务端 DataScope 执行 Data Query，生成已校验的只读事实快照。
2. 仅将该快照和明确的文档表达要求传给 Office AI / Master，生成公文内容。

前端只允许调用一个聚合入口并接收一条聚合 SSE 流。前端不得先调用 `/api/ai/data-query/chat`，再把结果拼成文本 Prompt 调用 `/api/ai/office/chat` 或 `/api/ai/master/chat`。两个独立接口的连续调用不构成 composite 能力，也不能绕过服务端事实锁定。

### 3.2 大模型只能表达，不能改数

大模型的输入必须是服务端产生的、带校验信息的只读 JSON 上下文。模型只能：

- 选择已返回事实的组织、期间、指标和顺序；
- 生成标题、摘要、通知、报告段落和格式化表达；
- 在不改变含义的前提下进行语言润色。

模型不得：

- 修改、四舍五入、重算、合并或拆分事实数值；
- 根据常识、历史文本或上下文补齐不存在的数字；
- 生成问数结果没有返回的同比、环比、排名、比例、原因或结论；
- 把同期相关线索写成生产因果结论；
- 覆盖 `dataInfo` 的指标名、统计期间、数据截止日期、单位和组织范围。

服务端必须在文档生成完成前执行事实一致性校验。发现数字、单位、期间、组织或事实状态漂移时，不得发出成功完成事件，应返回明确错误并保留已验证数据结果。

## 4. 建议路由

```http
POST /api/ai/composite/data-to-doc
Accept: text/event-stream
Content-Type: application/json
X-Request-Id: <client request id>
X-Portal-Identity: <signed portal identity>
```

### 4.1 路由语义

- 该路由是唯一的跨能力编排入口。
- 路由内部必须执行 Data Query 阶段，再执行 Office AI / Master 阶段。
- 路由不得把浏览器传来的 `metrics`、`table`、`chart`、`dataInfo` 或拼接后的事实文本当作权威输入。
- 请求中的身份以 Gateway 签名身份为准，不能由 JSON body 中的用户、组织、租户或权限字段覆盖。
- 请求必须支持幂等键，建议使用 `requestId`，同一租户、用户和 requestId 的重复请求不得重复产生不可追踪的文档任务。

## 5. 请求体标准

以下是建议的 v1 请求体。字段名称和枚举在后端正式实现前仍需通过 Gateway API 评审，但事实输入和权限边界不可放宽。

```json
{
  "protocolVersion": "2.0",
  "requestId": "uuid",
  "conversationId": "opaque-conversation-id",
  "dataQuery": {
    "query": "今年各项目公司发电量情况",
    "analysisType": "OVERVIEW",
    "sourceRequestId": "optional-previous-query-id"
  },
  "document": {
    "documentType": "REPORT",
    "title": "项目公司发电量情况报告",
    "instruction": "请整理为内部汇报材料，保留数据口径和事实边界",
    "format": "MARKDOWN",
    "audience": "INTERNAL"
  },
  "clientContext": {
    "assistantMode": "data-query",
    "timezone": "Asia/Shanghai"
  }
}
```

### 5.1 请求字段约束

| 字段 | 必填 | 约束 |
|---|---:|---|
| `protocolVersion` | 是 | 当前建议固定为 `2.0`。不支持的版本直接拒绝，不静默转换。 |
| `requestId` | 是 | 客户端生成的幂等追踪 ID；Gateway 应校验格式、长度和重复语义。 |
| `conversationId` | 否 | 只能使用服务端签发或已绑定的 opaque handle，不能承载权限。 |
| `dataQuery.query` | 是 | 用户的问数意图。服务端重新解析并执行，不接受浏览器传入的事实结果。 |
| `dataQuery.analysisType` | 否 | 只能作为分析意图提示，最终类型由服务端能力和协议决定，不能凭枚举宣称已支持。 |
| `dataQuery.sourceRequestId` | 否 | 仅用于服务端查找同一用户、同一权限范围内的已验证结果；查不到或已过期时必须重新查询。 |
| `document.documentType` | 是 | 服务端允许集合，例如 `NOTICE`、`REPORT`、`SUMMARY`；未知类型拒绝。 |
| `document.instruction` | 是 | 只描述表达、受众和格式，不得被解释为改数或改口径指令。 |
| `document.format` | 是 | 当前建议 `MARKDOWN`；其他格式须有对应安全输出契约。 |
| `clientContext` | 否 | 仅用于展示和审计辅助，不能用于身份、租户、组织或权限授权。 |

### 5.2 明确禁止的请求字段

以下字段不得作为客户端请求中的权威输入；即使出现，也必须被 Gateway 忽略或拒绝：

- `metrics`、`table`、`chart`、`insights`、`evidence`、`dataInfo`；
- `verifiedData`、`dataSnapshot`、`dataSnapshotHash` 等事实快照内容；
- `userId`、`tenantId`、`orgCode`、`allowedOrgCodes`、`allowedIndicatorCodes`；
- `systemPrompt`、`masterPrompt`、`officePrompt` 或由前端拼接的完整 Prompt；
- `skipValidation`、`trusted`、`allowAllOrganizations` 等权限或校验开关。

## 6. 服务端两阶段处理

### 6.1 阶段一：Data Query Truth

服务端必须：

1. 从签名请求解析 user、tenant 和门户身份，服务端查询 DataScope。
2. 校验组织范围、指标范围、时间口径和数据权限，并将权限绑定到实际查询执行边界。
3. 执行问数并完成协议、数据状态和口径校验。
4. 生成不可变的 `dataSnapshot`，记录 `snapshotId`、规范化 JSON 哈希、生成时间、数据截止日期和授权范围摘要。
5. 先发送 `data_ready`，明确该快照是否可用于文档生成。

`dataSnapshot` 只读且只在服务端可信边界内产生。客户端不能替换快照内容、哈希、权限范围或数据截止日期。

### 6.2 阶段二：Office AI Presentation

只有在阶段一返回可用事实快照后，服务端才能调用 Office AI / Master：

- 输入包含结构化只读事实快照、原始事实状态、数据口径和文档表达要求；
- 输入必须明确告诉模型不得改动数值和口径；
- 服务端不得把快照降级为无边界的长字符串 Prompt；
- 模型输出必须经过数值、单位、期间和组织范围一致性校验；
- 校验通过后才允许发送 `completed`；
- 校验失败时保留 `data_ready` 事实结果，文档部分进入失败或数据结果降级。

若阶段一为 `NO_DATA`、`ACCESS_DENIED`、`PROTOCOL_INVALID` 或其他不可用于写作的状态，服务端不得调用 Office AI，应直接结束为数据结果或错误结果。

## 7. 聚合 SSE 响应标准

前端只消费该路由返回的单一 SSE 流。所有事件都必须携带相同的 `requestId` 和 `compositeRequestId`，并按服务端序列递增。

### 7.1 事件顺序

成功路径：

```text
data_ready -> doc_streaming (one or more) -> completed
```

失败路径可以在任一阶段发送 `error`，但不能在事实校验失败后伪造 `completed`。网络重连时使用 SSE `id` / `Last-Event-ID` 恢复服务端事件，不由前端重新拼接 Prompt 或自行重复第二阶段。

### 7.2 公共事件包络

```json
{
  "protocolVersion": "2.0",
  "compositeRequestId": "uuid",
  "requestId": "uuid",
  "sequence": 1,
  "serverTime": "2026-09-03T12:00:00+08:00",
  "phase": "data-query",
  "payload": {}
}
```

### 7.3 `data_ready`

表示问数阶段已完成，服务端已经形成事实快照。该事件必须先于任何文档文本事件发送。

```text
event: data_ready
id: 1
data: {"protocolVersion":"2.0","compositeRequestId":"uuid","requestId":"uuid","sequence":1,"phase":"data-query","payload":{"status":"SUCCESS_WITH_DATA","dataSnapshot":{"snapshotId":"snapshot-id","snapshotHash":"sha256:...","readonly":true,"content":{"title":"问数结果","summary":"...","metrics":[],"table":null,"chart":null,"insights":[],"evidence":[],"dataInfo":{},"followUps":[]}}}}
```

约束：

- `payload.dataSnapshot.content` 只能来自服务端 Data Query 的已验证只读结果；
- `metrics` 中的数值、单位和标签必须保持问数结果原样；
- `dataInfo` 必须包含实际指标和统计期间/截止日期时才可发送，不得从前端猜测；
- `snapshotHash` 必须按服务端约定的规范化 JSON 计算，不能使用客户端提交的 hash；
- `status` 为无数据、拒绝或协议失败时，必须明确 `documentEligible: false`，不可进入 `doc_streaming`。

### 7.4 `doc_streaming`

表示 Office AI / Master 正在输出表达层内容。每个事件只传递服务端校验范围内的增量。

```text
event: doc_streaming
id: 2
data: {"protocolVersion":"2.0","compositeRequestId":"uuid","requestId":"uuid","sequence":2,"phase":"office-ai","payload":{"delta":"根据已核验数据，现将本期情况整理如下。","snapshotId":"snapshot-id","format":"MARKDOWN"}}
```

约束：

- `snapshotId` 必须与 `data_ready` 一致；
- `delta` 只表示文档表达，不代表新的数据查询结果；
- 服务端必须对累计文档执行数字和口径一致性校验，不能等前端拼接完成后再信任；
- 如果模型输出了快照中不存在的数字、单位、期间、组织或未经数据支持的因果结论，发送 `error`，错误码建议为 `FACT_DRIFT_DETECTED`。

### 7.5 `completed`

表示聚合任务已结束。只有文档校验通过，才能使用完整成功状态。

```text
event: completed
id: 3
data: {"protocolVersion":"2.0","compositeRequestId":"uuid","requestId":"uuid","sequence":3,"phase":"completed","payload":{"status":"COMPLETED","snapshotId":"snapshot-id","document":{"format":"MARKDOWN","content":"..."},"validation":{"numericConsistency":"PASS","scopeConsistency":"PASS","periodConsistency":"PASS","snapshotHash":"sha256:..."}}}
```

建议状态：

| 状态 | 语义 | 前端应见行为 |
|---|---|---|
| `COMPLETED` | 事实快照和文档表达均校验通过 | 展示文档，并保留事实来源/口径信息 |
| `COMPLETED_WITH_DATA_ONLY` | 问数成功，文档生成失败或未被允许 | 展示已核验问数结果，不伪装成完整公文 |
| `NO_DATA` | 问数阶段无可用数据 | 展示中性无数据结果，不调用模型 |
| `ACCESS_DENIED` | 身份或 DataScope 不允许 | 展示访问阻断，不泄露数据 |
| `FAILED` | 编排、模型或一致性校验失败 | 展示错误和可用的已核验数据结果 |

### 7.6 `error`

错误事件至少包含：`code`、`message`、`phase`、`retryable` 和 `preservedDataSnapshot`。错误消息不得泄露 SQL、密钥、内部 Prompt 或其他租户数据。

建议错误码：

| 错误码 | 阶段 | 说明 |
|---|---|---|
| `COMPOSITE_NOT_ENABLED` | Gateway | 公开编排接口尚未启用，当前状态即为此类后端阻断 |
| `DATA_QUERY_FAILED` | Data Query | 问数执行失败 |
| `DATA_SNAPSHOT_INVALID` | Data Query | 事实快照校验失败 |
| `FACT_DRIFT_DETECTED` | Office AI | 文档数字、单位、期间或范围与事实快照不一致 |
| `DOCUMENT_GENERATION_FAILED` | Office AI | 公文生成失败 |
| `COMPOSITE_TIMEOUT` | Gateway | 任一阶段超时 |
| `ACCESS_DENIED` | Gateway/Data Query | 服务端身份或 DataScope 校验失败 |

## 8. 防篡改与一致性约束

### 8.1 身份和权限

- 只信任 Gateway 验证通过的签名身份，不能信任 body 中的身份和组织字段。
- DataScope 必须同时约束组织、指标和集团/全组织能力，并进入实际数据执行边界。
- 阶段一和阶段二必须使用同一已验证身份、租户和权限快照；不能在第二阶段扩大范围。
- 数据快照过期、权限变化或会话归属变化时，必须重新问数，不得复用旧快照。

### 8.2 事实快照

- 快照使用规范化 JSON 和服务端生成的 `snapshotHash` 固定。
- 模型输入引用 `snapshotId` 和只读快照；模型不能写回快照。
- `data_ready` 后任何客户端输入都不能覆盖快照中的事实字段。
- 事实数值、单位、指标名、组织范围、时间口径和状态必须可审计回指到问数结果。

### 8.3 公文数值锁定

服务端至少校验以下内容：

1. 文档中出现的数值是否存在于事实快照，或是否为允许的原样格式化结果。
2. 数值单位、正负号、百分比、排名和小数精度是否一致。
3. 文档中提及的指标、组织和期间是否存在于快照。
4. 文档是否把 `insights/evidence` 的相关线索升级成未经支持的因果结论。
5. 文档最终校验使用的 `snapshotHash` 是否与 `data_ready` 相同。

校验失败时必须阻断完整公文成功态，保留已验证事实结果，并记录 `FACT_DRIFT_DETECTED` 审计事件。

## 9. 审计、超时与幂等

- `requestId`、`compositeRequestId`、`snapshotId`、`snapshotHash`、用户/租户、阶段状态、错误码、模型版本和一致性校验结果必须进入服务端审计。
- 审计记录不能保存真实密钥；敏感 Prompt 和大段文档内容按服务端脱敏/留存策略处理。
- Data Query 阶段和 Office AI 阶段都必须有独立超时，并有总超时上限。
- 阶段一失败不得启动阶段二；阶段二失败不得丢弃阶段一已验证结果。
- 同一幂等请求重试时，服务端应复用可复验的快照或返回明确的已完成结果，不能造成权限范围漂移。
- SSE 断线恢复必须由服务端按事件 ID 提供一致序列，不能由浏览器自行补发 Office AI 请求。

## 10. 前端接入前置条件

在以下条件全部满足前，前端保持当前独立能力和现有降级，不新增协同入口：

- Gateway 正式发布 `/api/ai/composite/data-to-doc`，并提供 OpenAPI/JSON Schema；
- 服务端提供 `data_ready -> doc_streaming -> completed` 的真实 SSE 样例和错误样例；
- 有效签名身份、租户、组织范围、指标范围和集团权限进入同一执行边界；
- `snapshotHash`、数值一致性、因果边界和失败保留数据结果有自动化契约测试；
- 超时、断线恢复、幂等、审计和权限变化场景完成联调；
- 明确文档生成失败时的 `COMPLETED_WITH_DATA_ONLY` 语义和用户可见文案。

在后端契约正式可达之前，任何前端实现都只能显示能力未开放或继续使用已核验的数据结果，不能把本地两次 API 调用包装为跨能力协同。
