# 二期 File Hub 平台级附件支撑中心架构设计与待办规划

更新时间：2026-09-03  
建设阶段：二期专项建设，Task 7 延期归档  
一期关系：不阻塞当前主线发布，不进入一期只读指标库变更范围

## 一、业务背景与建设目标

File Hub 不是当前右侧助手的局部上传控件，而是面向多个能力的附件支撑中心。二期需要把文件的上传、解析、权限、引用、生命周期和导出统一成可审计的平台能力，至少服务以下场景：

1. 公文多模态上下文起草：接收并引用 Word、PPT、PDF、图片等材料，为制度核对、会议纪要、通知和公文草拟提供可追溯上下文。
2. 线下私有表格沙箱即席计算：在隔离环境中处理用户上传的 Excel/CSV 等表格，优先评估 DuckDB/SQLite 的只读导入、临时计算和结果清理能力，不把用户文件直接送入一期指标查询链路。
3. 高保真 Word/PPT 导出：保留版式、表格、批注、图片和必要的文档元数据，支持从已核验事实和公文内容生成可交付的 Word/PPT 文件。

建设目标是形成独立的文件对象、解析产物、引用关系、临时计算任务和导出任务边界；任何 AI 应用只能通过受控引用拿到已授权的文件内容，不能凭借浏览器传入的文件标识越权读取对象。

## 二、目标架构边界

```text
门户/助手前端
    │ 仅拿短期上传句柄、引用句柄和任务状态
    ▼
AI 网关：上传流式鉴权、租户/用户校验、审计、限流
    ├── File Hub API：对象元数据、引用、生命周期、下载签名
    ├── 解析微服务：Apache POI / Tika，抽取结构化文本和版式元数据
    ├── 私有表格沙箱：DuckDB / SQLite，临时库、只读导入、资源配额
    └── 导出服务：高保真 Word/PPT 生成与结果回写
             │
             ▼
      MinIO / 临时对象存储
```

一期的只读指标库、指标语义字典、问数 SQL 执行服务和既有 DataScope 不属于 File Hub 的可直接修改对象。文件上下文若要参与智能问数，必须经过二期单独评审的契约、脱敏和租户隔离，不得通过前端拼接 Prompt 绕过 Gateway。

## 三、开发前置依赖与待办

以下事项全部完成并留有可复核证据后，才进入 File Hub 编码：

| 前置依赖 | 必须交付的内容 | 验收重点 |
|---|---|---|
| MinIO / 临时对象存储接入 | 对象桶、生命周期、临时下载签名、加密和清理策略 | 对象不可被公网直读；过期对象可回收；租户前缀不可互读 |
| Apache POI / Tika 解析微服务 | Word/PPT/Excel/PDF 的 MIME 识别、解析、页/段/表格结构和失败码 | 文件类型与大小白名单；恶意文档隔离；解析失败不伪造内容 |
| AI 网关上传流式鉴权 | 上传、分片/流式传输、断点/超时、任务状态 SSE 和审计契约 | 服务端身份为唯一可信身份；上传句柄、引用句柄和任务句柄不可互换 |
| 脱敏与租户级 DataScope 隔离 | 内容脱敏规则、租户/用户/组织范围、引用级授权和审计字段 | 原文、解析文本、缓存、导出物均执行同一租户边界；拒绝越权引用 |

建议同步冻结：最大文件大小与总配额、病毒/宏文件处理、解析超时、沙箱 CPU/内存/磁盘配额、对象保留周期、导出水印、错误与审计事件字典，以及跨能力引用的快照哈希规则。

## 四、分阶段待办规划

### 4.1 契约与安全设计

- [ ] 建立 File Hub 对象、文件版本、解析产物、引用句柄、临时计算任务和导出任务的数据模型。
- [ ] 输出上传、查询元数据、引用内容、下载、删除、过期清理和任务 SSE 的 OpenAPI/JSON Schema。
- [ ] 完成租户级 DataScope、组织权限、用户身份、Origin 白名单、审计和幂等策略的安全评审。
- [ ] 明确脱敏发生在原文解析前、结构化产物生成前还是 AI 引用前，并为每层定义不可逆边界。

### 4.2 基础设施与解析

- [ ] 接入 MinIO 或等价临时对象存储，完成加密、生命周期和故障恢复演练。
- [ ] 建设 POI/Tika 解析微服务，提供结构化文本、表格、图片/页码引用和解析失败原因。
- [ ] 建设隔离的 DuckDB/SQLite 临时表格沙箱，禁止访问一期数据库和内部网络，补齐资源配额与清理任务。

### 4.3 Gateway 与业务接入

- [ ] 在 AI Gateway 增加上传流式鉴权、租户/用户校验、短期句柄签发、限流和审计。
- [ ] 先以公文上下文起草为试点，验证引用快照、来源展示、脱敏和失败降级。
- [ ] 再接入私有表格即席计算，确保计算结果只能作为临时事实返回，不写入一期指标库。
- [ ] 最后接入高保真 Word/PPT 导出，验证图片、表格、版式和事实快照一致性。

### 4.4 验收与发布

- [ ] 完成恶意文件、超限文件、过期句柄、重复请求、跨租户引用、伪造用户和越权组织的负向测试。
- [ ] 完成解析准确性、沙箱资源隔离、导出保真度、对象清理和 20 并发基线测试。
- [ ] 形成独立生产发布清单、回滚方案、监控指标和审计查询样例。

## 五、分支与一期隔离纪律

- 二期必须另立专属分支：`feat/file-hub-platform`。
- 严禁侵入一期只读指标库：不得修改 `huanbao-dataquery/` 的现有查询执行、指标字典、SQL 资产、生产数据表或既有 DataScope 代码来承载 File Hub。
- 不得在一期前端偷偷增加上传入口、文件直链、附件字段或浏览器端文件转 Prompt 逻辑；在正式契约和安全评审完成前，Task 7 保持 `OPTIONAL_SKIPPED`。
- 二期与一期的交互只能通过经评审的 Gateway 契约完成，并保留数据快照、权限判定和审计证据。
