# 操作审计设计

更新时间：2026-09-02

当前状态：Gateway 已提供动作审计写入和查询接口，DDL 文件已存在；前端 sendIgixAction 当前只向 iGIX 父页面发送动作，没有自动调用审计接口。本次线上查询返回 total=0，因此不能声称已有动作落库。

## 1. 审计对象

审计记录的是流程助手动作尝试，不是权限授予，也不是业务执行回执。当前已验证动作是打开采购请示单：

- action：open_form
- formCode：CGQSD
- funcId：9744034a-7fcc-4510-97fa-f563aecd26e6
- status：verified
- hasFields：false

## 2. 字段和安全

核心字段包括 actionId、userId、userName、query、action、formCode、funcId、status、hasFields、sentAt、result、errorMessage、clientIp、userAgent 和 createdAt。

- 不保存完整 fields、Dify Key、数据库密码或大图片字段。
- query 和 errorMessage 必须限制长度并按需要脱敏。
- actionId 用于去重，服务端时间作为入库时间。
- 审计写入接口不能接受浏览器伪造的权限结论。
- 查询和写入接口上线前应补充管理员或签名身份鉴权；当前代码的 action-audits Controller 尚未形成完整的访问控制。

## 3. 数据库

建表文件是 docs/sql/ai_action_audit.sql。本次只读检查了 DDL，没有执行 SQL，也没有连接线上数据库。上线前需要确认表、索引、保留周期、归档和告警策略。

## 4. 闭环目标

后续应由动作桥接层发送前先生成 actionId，Gateway 接收最小事件并落库；iGIX 父页面回传成功或失败后，再用同一 actionId 记录最终结果。发送成功、业务打开成功和审计落库成功必须在界面和日志中分开表达。
