# 操作审计设计

## 目标

流程助手动作通过前端 `postMessage` 发送给 iGIX 父页面。AI Gateway 第一版补充服务端审计入口，用于记录前端产生的流程助手操作事件，便于后续排查、统计和审计。

第一版只做审计落库，不做真实权限判断，不执行流程动作。

## 审计字段

| 字段 | 说明 |
|---|---|
| `actionId` | 前端生成的动作唯一标识，必填，唯一。 |
| `userId` | 当前用户 ID，可为空。 |
| `userName` | 当前用户姓名，限制长度。 |
| `query` | 用户原始输入，限制长度，避免超长文本。 |
| `action` | 动作类型，例如 `open_form`、`open_menu`。 |
| `formCode` | iGIX 表单或菜单编码。 |
| `funcId` | iGIX 功能 ID。 |
| `status` | 前端入口状态，例如 `verified`。 |
| `hasFields` | 是否包含字段预填。试点上线版应为 `false`。 |
| `sentAt` | 前端发送时间。 |
| `result` | 前端动作结果，例如 `sent`、`failed`。 |
| `errorMessage` | 失败原因。 |
| `clientIp` | 服务端从请求中提取。 |
| `userAgent` | 服务端从请求头提取。 |
| `createdAt` | 服务端入库时间。 |

## 安全边界

- 不保存完整 `fields`。
- 不保存 Dify API Key。
- 不保存用户头像、图片等大字段。
- `query` 和 `errorMessage` 限制最大长度。
- 审计只记录操作，不代表权限校验通过。

## 数据库

建表 SQL：

```text
docs/sql/ai_action_audit.sql
```

核心索引：

- `action_id` 唯一索引。
- `user_id` 普通索引。
- `action` 普通索引。
- `form_code` 普通索引。
- `result` 普通索引。
- `created_at DESC` 普通索引。

## 后续建议

1. 接入服务端认证，避免匿名写入审计。
2. 接入真实 iGIX 权限校验结果。
3. 增加动作执行回调，记录最终打开成功或失败。
4. 增加审计日志归档策略。
5. 增加敏感字段脱敏策略。
