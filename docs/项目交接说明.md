# 项目交接说明

## 项目背景

环宝 AI 智能助手是面向企业办公门户的右侧嵌入式 AI 助手前端项目。项目目标是在不改变现有门户主业务的前提下，为员工提供统一 AI 入口，用于查制度、写材料、办流程。

## 建设目标

- 形成可嵌入门户的 AI 助手面板。
- 打通制度知识库问答。
- 打通办公材料处理 Agent。
- 为流程办理提供前端动作卡片和后续 iGIX 对接入口。
- 支持历史、复制、导出等实际办公复用能力。

## 当前完成情况

当前版本为 V1：可演示、可使用的企业门户 AI 助手前端。

已完成：

- 企业门户右侧助手 UI。
- 三种助手模式。
- 自动意图识别和分发。
- 制度问答 Dify blocking。
- 办公智能 Dify Agent streaming。
- `<think>` 内容过滤。
- Markdown 渲染。
- 引用来源展示和原文展开。
- 流程助手动作卡片。
- AI 回复复制、导出 Markdown、导出 Word/HTML。
- 本地历史搜索、筛选、删除、清空。

## 系统能力

### 制度问答

用于查询公司制度、管理办法、报销标准、审批依据。返回结果展示引用来源，支持展开知识库原文片段。

### 办公智能

用于整理会议纪要、润色材料、生成通知公告、工作总结、摘要提炼。该模式接入 Dify Agent streaming。

### 流程助手

用于识别流程事项并展示动作卡片。当前不打开真实表单，仅展示演示动作。已配置采购请示单、合同评审流程、我的待办。

## 产品形态

- 可独立访问。
- 可通过 iframe 嵌入企业门户右侧区域。
- Header / ChatBody / Footer 三段式结构。
- 历史弹层和模式切换均为轻量浮层，不做抽屉。

## 技术实现

- Vue 3 + Vite 单页应用。
- Dify API 由前端直接调用。
- localStorage 存储当前会话和历史。
- Nginx 静态部署 dist。

## 前端和 Dify 的关系

前端负责模式选择、意图识别、消息渲染、历史和导出。Dify 负责制度问答和办公智能回答生成。

- 制度问答：blocking。
- 办公智能：streaming。
- 流程助手：不接 Dify。

## 前端和门户 / iGIX 的关系

当前前端尚未与门户父页面或 iGIX 真实表单联动。流程助手动作卡片是后续对接入口。下一步应通过 postMessage 将“打开菜单、打开表单、预填字段”等动作交给门户 / iGIX / 后端工具执行。

## 当前限制

- API Key 通过 Vite 前端环境变量注入，生产环境更安全的方式是后端代理。
- 历史记录仅在浏览器 localStorage，不跨设备。
- 流程助手不执行真实业务动作。
- 未接用户身份、权限、审计。

## 风险点

- 前端直连 Dify 会暴露 Key 给浏览器运行环境。
- Agent 应用必须 streaming，不能误用 blocking。
- 流程助手真实动作必须经过门户/iGIX权限校验，不能由 Dify 直接执行。
- localStorage 不适合作为正式审计记录。
