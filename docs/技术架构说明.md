# 技术架构说明

更新时间：2026-09-15

本文只描述当前代码、当前生产链路和已经确认的目标方向。历史架构不在本文件重复保存。

## 1. 当前架构快照

```text
iGIX 门户父页面
  ├─ iframe 窗口控制、用户身份握手、门户动作 ACK
  └─ Vue 3 环宝 AI 助手
       ├─ 制度/办公/Master -> AI Gateway -> 存量 Dify 兼容代理
       ├─ 智能问数 -> AI Gateway -> huanbao-dataquery:8089
       ├─ 流程助手 -> 前端规则 -> IGIX_AI_ACTION
       └─ localStorage -> 当前会话与历史

AI Gateway
  ├─ HMAC 签名身份、DataScope、限流、会话和审计
  ├─ 制度、办公、Master 的 Dify 兼容代理
  └─ 问数安全转发，不负责问数计划、SQL 或公式计算

huanbao-dataquery
  ├─ 意图识别和会话状态
  ├─ 指标/组织语义解析
  ├─ 受控 SQL 和半年分表查询
  ├─ 公式、单位和时间语义计算
  ├─ 统计、排名、同比环比和数据质量
  └─ v2 结构化协议与 SSE
```

## 2. 服务职责

| 服务 | 当前职责 | 明确不负责 |
|---|---|---|
| Vue 前端 | 模式分发、会话展示、结构化结果渲染、流程动作发起 | 不持有密钥，不决定权限，不重算后端事实 |
| AI Gateway | 门户身份校验、授权查询、会话归属、限流、审计和 SSE 代理 | 不执行问数 SQL，不信任浏览器权限字段 |
| `huanbao-dataquery` | 受控意图、语义、SQL、公式、时间、排名、数据质量和 v2 协议 | 不暴露数据库细节，不接受浏览器绕过 Gateway |
| Dify 兼容层 | 迁移期间承接制度、办公和 Master | 不再承接智能问数生产查询 |
| iGIX 父页面 | 用户上下文、窗口状态、权限和门户动作 ACK | 不把子页面消息本身当作授权依据 |

## 3. 当前问数调用链

```text
Browser
  -> POST /api/ai/data-query/access
  -> POST /api/ai/data-query/chat (SSE)
  -> Gateway 签名身份与服务端 DataScope
  -> POST http://127.0.0.1:8089/api/query/execute
  -> huanbao-dataquery 意图、查询、计算、协议组装
  -> Gateway 原样转发 SSE
  -> DataQueryResult / DataQueryChart
```

当前生产有效身份查询已验证：2025 年生活垃圾入厂量为 `2165.683098 万吨`，12 个月；2025 年和 2026 年项目公司排名均覆盖授权范围内 63 家组织。业务参考图的 `2181.85 万吨` 尚未对账完成，不得写入代码或 Prompt。

## 4. 当前结果与降级

- v2 结构化视图要求 `protocolVersion = 2.0` 且 `protocolValid = true`。
- 结构化内容必须在 `content` 下，包含 title、summary、metrics、table、chart、insights、evidence、dataInfo 和 followUps 等字段。
- 版本不符、协议损坏或缺少 content 时，前端进入可信文本/协议降级，不自行从文本猜指标和数字。
- 后端 `NO_DATA` 与前端旧分支 `NO_DATA_IN_PERIOD` 仍有命名偏差，统一前必须保留中性空态。
- 页面提示“暂未获取到该维度的结构化分析数据”只表示没有收到可通过校验的 v2 结果，不等于数据库无数据。
- 页面提示“执行失败”是通用错误；排查必须使用 requestId 关联 Gateway 和 8089 日志。

## 5. 当前安全边界

- 生产问数默认使用 `SIGNED_HEADER`，身份由 Gateway 校验 `X-Portal-Identity`、时间戳和 HMAC。
- Gateway 按 `tenantId + userId` 查询服务端授权；浏览器 body 中的用户、组织、指标和权限字段不能覆盖服务端结果。
- 组织范围已经进入问数执行链；指标范围、集团排名和全组织权限仍需继续核验是否完整进入执行边界。
- Dify Key、数据库凭据、签名密钥和服务器密码只存在服务端受控配置，不进入 Vite 构建产物、文档或 Git。
- iGIX 动作必须校验 source、Origin、消息类型和 actionId；发送 postMessage 不等于业务完成。

## 6. 当前架构缺口

- 指标语义、组织映射、业务参考报表和数据库源表还没有统一成一个带版本的权威目录。
- v2 和旧文本兼容逻辑并存，前端仍有历史兼容计算路径。
- 制度知识库、模型调用和办公模板尚未独立服务化，Dify 兼容层尚未下线。
- 生产问数和业务参考图的组织范围、快照、源表和口径差异尚未关闭。
- 流程父页面 ACK、真实权限和服务端动作审计尚未形成完整闭环。

## 7. 去 Dify 化目标

```text
门户
  -> AI Gateway
       ├─ Model Adapter / Prompt Registry
       ├─ Knowledge Service / Citation
       ├─ Data Query Service / Semantic Layer
       ├─ Office Service
       └─ Workflow Service
            -> KingbaseES / MinIO / OpenSearch / 业务系统
```

目标范围、数据模型、API、Wave、验收、发布和下线步骤见[去 Dify 化智能助手整体建设方案](./去Dify化智能助手整体建设方案.md)。
