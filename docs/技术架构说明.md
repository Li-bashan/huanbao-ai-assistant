# 技术架构说明

更新时间：2026-07-22

## 总体架构

```text
iGIX 门户父页面
  ├─ 控制 iframe 小窗 / 中窗 / 全屏 / 关闭
  ├─ 消费 IGIX_AI_ACTION 并调用 iGIX 菜单/表单能力
  └─ iframe：Vue 3 环宝 AI 助手
       ├─ 制度问答 -> Dify blocking（当前前端直连）
       ├─ 办公智能 -> Dify Agent SSE（当前前端直连）
       ├─ 流程助手 -> 前端规则 + 动作卡片
       └─ localStorage -> 当前会话与历史

AI Gateway（仓库内已实现，前端尚未接入）
  ├─ 制度问答代理
  ├─ 流程动作校验
  └─ 动作审计
```

## 三种消息链路

### 制度问答

`sendChatMessage` 使用 `response_mode: blocking`。返回后从 `metadata.retriever_resources` 规范化引用，最多展示 3 条资源。当前读取 `VITE_POLICY_DIFY_API_BASE` / `VITE_POLICY_DIFY_API_KEY`，并兼容旧的通用变量。

### 办公智能

`streamChatMessage` 使用 `response_mode: streaming`，通过 `ReadableStream`、`TextDecoder` 和 SSE `data:` 行处理 `message`、`agent_message`、`message_end`、`error`。前端按完整累计文本替换渲染，并过滤 `<think>`。

### 流程助手

流程助手不调用 Dify。`detectWorkflowAction` 返回流程卡片；只有 `verified` 且映射完整的入口生成 action payload。点击后由 `sendIgixAction` 发送到父页面。

## iGIX 动作协议

```js
window.parent.postMessage({
  type: 'IGIX_AI_ACTION',
  payload: {
    action: 'open_form',
    formCode: 'CGQSD',
    funcId: '9744034a-7fcc-4510-97fa-f563aecd26e6',
    actionId: '由 bridge 注入'
  }
}, '*')
```

`actionBridge` 递归解包 Vue ref/Proxy，只保留可克隆的普通对象、数组和基础类型，并使用 `structuredClone` 做发送前校验。当前动作 targetOrigin 仍为 `*`，待生产收口。

## 窗口控制协议

助手发送：

```js
{ type: 'IGIX_ASSISTANT_WINDOW', action: 'compact|wide|toggle-wide|fullscreen|toggle-fullscreen|close|get-state|escape' }
```

父页面回传：

```js
{
  type: 'IGIX_ASSISTANT_WINDOW_STATE',
  state: { view: 'compact|wide|fullscreen', isOpen: true, iframeLoaded: true }
}
```

窗口协议的 targetOrigin 优先从 `document.referrer` 推导，无法推导时回退到已知 iGIX origin。接收状态时同时校验 `event.source` 和 `event.origin`。

## 当前用户

`igixUser` 按 `top -> parent -> self` 查找 `gspframeworkService.common.userInfos.get()`，只保留 `userId`、`code`、`name`、`mobilePhone`、组织和租户等白名单字段。当前仅 `name` 用于欢迎语；预填关闭时不会把用户信息写入动作。

## 历史与导出

- localStorage key：`huanbao_current_conversation`、`huanbao_conversation_history`、`huanbao_current_mode`。
- 历史最多 50 条，不保存 loading/streaming 中间态。
- 导出 Word 使用 HTML `.doc`，不引入复杂文档依赖。

## AI Gateway

`ai-gateway/` 是 Java 17 + Spring Boot + PostgreSQL 服务，提供健康检查、制度问答代理、动作校验和审计 API。当前前端没有调用这些 API，因此网关属于“代码已具备、接入未完成”。

## 安全边界

- 生产环境应通过 AI Gateway 隐藏 Dify Key。
- 父页面必须校验权限并按 `actionId` 幂等消费动作。
- `IGIX_AI_ACTION` 应配置明确 targetOrigin。
- 不发送自动提交动作。
- localStorage 不能替代服务端审计。
