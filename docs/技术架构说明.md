# 技术架构说明

## 总体架构

本项目是前端单页应用，部署为 Nginx 静态站点。浏览器端直接调用 Dify API，并使用 localStorage 存储本地会话。

```text
用户浏览器
  ├─ Vue 助手前端
  ├─ Dify 制度问答 blocking
  ├─ Dify 办公智能 streaming
  └─ localStorage 历史
```

## 前端架构

- `src/App.vue`：主页面、状态、发送、模式切换、历史、工具栏。
- `src/style.css`：全局样式。
- `public/`：环宝视觉素材。

## Dify 接入架构

文件：`src/services/chatApi.js`。

- `sendChatMessage`：blocking / Mock。
- `streamChatMessage`：streaming。
- `getDifyConfig`：按 modeKey 选择 Dify 应用配置。

## blocking 和 streaming 区别

制度问答使用 blocking：

- 一次请求。
- 一次返回完整 answer。
- 可解析 `metadata.retriever_resources`。

办公智能使用 streaming：

- Agent Chat App 不支持 blocking。
- 通过 SSE 逐段返回。
- 前端实时更新 assistant 消息。

## SSE 流式解析

`streamChatMessage` 使用：

- `fetch`
- `response.body.getReader()`
- `TextDecoder`
- 按行解析 `data:`

处理事件：

- `message`
- `agent_message`
- `message_end`
- `error`

## Markdown 渲染

文件：`src/utils/markdown.js`。

- 使用 `markdown-it`。
- 禁用原始 HTML。
- 使用 DOMPurify sanitize。
- 只对 assistant 消息使用 `v-html`。

## 引用来源处理

制度问答从 `metadata.retriever_resources` 解析引用：

- 按 `document_id` 优先去重。
- 无 document_id 时按 documentName。
- 最多展示 3 个不同文件。
- 支持展开 `content` 原文片段。

## 流程动作卡片

文件：`src/config/workflowActions.js`。

配置：

- 关键词。
- actions。
- requiredFields。
- description。

命中后 assistant 消息包含 `workflowCard`，模板渲染动作卡片。

## localStorage 历史

文件：`src/utils/conversationStorage.js`。

key：

- `huanbao_current_conversation`
- `huanbao_conversation_history`
- `huanbao_current_mode`

规则：

- 不保存 loading / streaming。
- 最多 50 条。
- 兼容旧历史结构。

## 导出功能

文件：`src/utils/messageExport.js`。

- 复制：纯文本。
- Markdown：Blob 下载 `.md`。
- Word/HTML：Blob 下载 `.doc`，Word/WPS 可打开。

## Nginx 静态部署

构建产物 `dist/` 由 Nginx 提供静态访问。服务器路径 `/LBSops/huanbao-ai-assistant`。

## 后续后端代理和权限方案

建议后续增加后端代理：

- 隐藏 Dify API Key。
- 注入用户身份。
- 做权限校验。
- 做审计日志。
- 代理门户 / iGIX 工具动作。
