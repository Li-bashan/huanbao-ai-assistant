# 技术架构说明

更新时间：2026-09-02

> 当前工作区存在未提交的统一 Master Gateway 改动。本文把代码已具备、线上已探测和目标环境待确认的边界分开描述。

## 总体架构

```text
iGIX 门户父页面
  ├─ 管理 iframe 小窗 / 中窗 / 全屏 / 关闭
  ├─ 消费 IGIX_AI_ACTION 并调用 iGIX 菜单/表单能力
  ├─ 提供当前用户和签名身份握手
  └─ iframe：Vue 3 环宝 AI 助手
       ├─ 制度/办公 -> Gateway Master SSE -> Dify
       ├─ 智能问数 -> Gateway access/chat SSE -> Dify -> Kingbase 插件或目标查询链路
       ├─ 流程助手 -> 前端规则 + 动作卡片
       ├─ 智能填单 -> 设计中的字段桥接，当前关闭
       └─ localStorage -> 当前会话与历史

AI Gateway
  ├─ HMAC 签名身份校验和问数服务端 DataScope
  ├─ 制度、办公、Master、问数 Dify 代理代码
  ├─ 限流、超时、统一错误和问数审计代码
  ├─ 问数人员管理 CRUD
  ├─ 流程动作校验和动作审计代码
  └─ Dify Key 只应存在服务端环境
```

## 能力链路

### 制度和办公

当前工作区页面：

```text
App.vue
  -> sendMasterChatMessage
  -> POST /api/ai/master/chat，SSE
  -> Gateway DIFY_MASTER_API_BASE/chat-messages
```

`chatApi.js` 仍保留 `sendGatewayPolicyMessage` 的 blocking 和 `streamGatewayOfficeMessage` 的 streaming，属于兼容实现，不等于页面当前一定走这两条路径。Master 改动目前未提交、未部署。

### 智能问数

```text
App.vue
  -> dataQueryApi.js
  -> POST /api/ai/data-query/access
  -> POST /api/ai/data-query/chat，SSE
  -> Gateway SIGNED_HEADER 身份校验
  -> ai_data_query_user DataScope
  -> opaque 会话映射、限流、审计
  -> Dify /chat-messages
  -> Gateway v2 校验/事件适配
  -> DataQueryResult / DataQueryChart
```

浏览器只应持有环宝客户端会话句柄；Dify conversation ID、API Key、SQL 和数据库连接信息留在服务端或 Dify 受控配置中。Dify 当前实际绑定的应用、发布版本和是否消费 `auth_*` 权限变量，本次尚未确认。

### 流程助手

流程助手不调用 Dify：`intentRouter` 命中 `workflowActions` 后展示动作卡片，只有 `verified` 且映射完整的入口才可点击。`actionBridge` 清洗 Vue Proxy/ref，生成 UUID `actionId`，使用解析后的门户 Origin 发送 `IGIX_AI_ACTION`。

### 智能填单

智能填单仍是设计方案。正式路径应是运行时字段元数据 -> 用户确认 -> `IGIX_AI_PREFILL_REQUEST` -> 门户打开表单 -> `IGIX_AI_PREFILL_READY/APPLY` -> `BindingData.setValue` -> `IGIX_AI_PREFILL_ACK`。当前 `ENABLE_WORKFLOW_PREFILL = false`，不发送字段。

## 身份和权限

Gateway 默认配置为 `DATA_QUERY_IDENTITY_MODE=SIGNED_HEADER`，使用：

```text
X-Portal-Identity
X-Portal-Identity-Timestamp
X-Portal-Identity-Signature
```

签名内容是 `timestamp + "." + signedIdentity` 的 HMAC-SHA256；解码身份至少需要 `userId` 和 `userName`。`BODY_TRIAL` 默认关闭，只能在明确的非生产联调中启用，不能当作正式认证。

问数授权按 `tenantId + userId` 查询 `ai_data_query_user`，返回组织范围、指标范围、集团排名和全组织开关。必须进一步确认这些范围进入 Dify/SQL 的实际执行边界；Gateway 接收到范围本身不代表数据库查询已经被限制。

## iGIX 协议

窗口控制：`IGIX_ASSISTANT_WINDOW` / `IGIX_ASSISTANT_WINDOW_STATE`。动作控制：`IGIX_AI_ACTION`。当前动作 target Origin 已由配置、referrer 或默认门户 Origin 解析，不再固定写死 `*`；生产仍应配置明确 Origin。

```js
{
  type: 'IGIX_AI_ACTION',
  payload: {
    action: 'open_form',
    formCode: 'CGQSD',
    funcId: '9744034a-7fcc-4510-97fa-f563aecd26e6',
    actionId: 'bridge 自动生成'
  }
}
```

父页面必须校验来源、权限和 `actionId` 幂等；发送成功只表示 `postMessage` 已调用，不代表表单已打开。当前未发现父页面执行回执和前端动作审计已形成闭环。

## 数据和历史

- `localStorage` 保存当前会话、历史和模式；最多 50 条，不跨设备。
- 问数结果按 v2 协议保存展示内容和分析状态，不应保存 Dify 技术节点或敏感连接信息。
- `docs/sql/` 只包含 Gateway 管控表 DDL/迁移。本次未执行 SQL，生产表存在性待目标数据库核验。

## 安全边界

- 生产 Dify Key 只能在 Gateway/Dify 服务器端环境。
- 浏览器的 `untrustedClientContext` 不能覆盖签名身份。
- Dify 直接 SQL 插件是否仍被目标工作流使用，必须通过应用绑定和工作流配置核对确认。
- 不允许前端传任意 SQL；查询应由受控语义层、白名单或固定查询服务约束。
- 不允许自动提交、自动审批或把没有 ACK 的动作显示成成功。
- localStorage 不能替代服务端审计。
