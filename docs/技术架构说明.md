# 技术架构说明

更新时间：2026-08-31

## 总体架构

```text
iGIX 门户父页面
  ├─ 控制 iframe 小窗 / 中窗 / 全屏 / 关闭
  ├─ 消费 IGIX_AI_ACTION 并调用 iGIX 菜单/表单能力
  ├─ 转发 IGIX_AI_PREFILL_REQUEST / APPLY / ACK
  └─ iframe：Vue 3 环宝 AI 助手
       ├─ 制度问答 -> AI Gateway -> Dify blocking
       ├─ 办公智能 -> AI Gateway -> Dify Agent SSE
       ├─ 流程助手 -> 前端规则 + 动作卡片
       ├─ 智能填单 -> 字段预览 + 表单桥接 ACK
       ├─ 智能问数 -> AI Gateway -> Dify 分析引擎 -> KingbaseES；前端按 v2 协议渲染
       └─ localStorage -> 当前会话与历史

AI Gateway
  ├─ 智能问数签名身份校验和服务端开放范围
  ├─ Dify /chat-messages 代理与 v2/SSE 适配
  ├─ 限流、超时、统一错误和查询审计
  ├─ 智能问数人员管理 CRUD
  ├─ 制度问答代理、流程动作校验和动作审计
  └─ Dify Key 仅存在服务端环境
```

## 四种能力链路

### 制度问答

`sendChatMessage` 通过 Gateway 使用 `response_mode: blocking`。返回后从 `metadata.retriever_resources` 规范化引用，最多展示 3 条资源。Dify Key 不进入前端。

### 办公智能

`streamChatMessage` 使用 `response_mode: streaming`，通过 `ReadableStream`、`TextDecoder` 和 SSE `data:` 行处理 `message`、`agent_message`、`message_end`、`error`。前端按完整累计文本替换渲染，并过滤 `<think>`。

### 流程助手

流程助手不调用 Dify。`detectWorkflowAction` 返回流程卡片；只有 `verified` 且映射完整的入口生成 action payload。点击后由 `sendIgixAction` 发送到父页面。

### 智能填单

助手先根据当前用户可访问的函数目录和当前表单字段描述，把自然语言解析成经过存在性、可编辑性和类型校验的字段。用户确认后向门户父页面发送 `IGIX_AI_PREFILL_REQUEST`。父页面从运行时目录或兼容覆盖中确认目标菜单并调用 `openMenu`，目标表单中的桥接器 ready 后接收 apply，并在 Farris-Angular 上调用 `frameContext.bindingData.setValue`。只有收到 `IGIX_AI_PREFILL_ACK` 才显示已回填；超时或拒绝时降级为打开表单、人工检查。

`rtcommon / fillform` 可以作为字段预览外观参考，但不承担字段写入。请见 `docs/智能填单表单桥接实施说明.md`。

### 智能问数

智能问数通过 `src/services/dataQueryApi.js` 调用 `POST /api/ai/data-query/chat`。Gateway 校验签名身份和服务端开放范围后，固定使用 Dify `/chat-messages` streaming，并将 Dify 内部事件适配成业务级 SSE。`conversationId` 按助手模式独立维护：首轮可为空，Gateway 创建用户专属句柄并在服务端映射到 Dify 会话；历史恢复和连续追问复用该句柄，制度问答和办公智能 ID 不会混入智能问数。页面不通过关键词猜分析类型、不从摘要解析数字，收到 v2 协议后交给 `DataQueryResult` 原生渲染，非法协议降级为摘要文本。

标题栏的 `CapabilitySelector` 只通过 props/emit 与 `App.vue` 交换当前 mode，不参与 Dify、流程动作或历史持久化。能力菜单数量、名称、图标和副文案均来自 `assistantModes`。

## iGIX 动作协议

```js
window.parent.postMessage({
  type: 'IGIX_AI_ACTION',
  payload: {
    action: 'open_form',
    formCode: 'CGQSD',
    funcId: '9744034a-7fcc-4510-97fa-f563aecd26e6',
    actionId: '由 bridge 注入'
  }
}, '*')
```

`actionBridge` 递归解包 Vue ref/Proxy，只保留可克隆的普通对象、数组和基础类型，并使用 `structuredClone` 做发送前校验。当前动作 targetOrigin 仍为 `*`，待生产收口。

字段回填不复用普通 `IGIX_AI_ACTION` 的成功语义，而使用 `IGIX_AI_PREFILL_REQUEST`、`IGIX_AI_PREFILL_READY`、`IGIX_AI_PREFILL_APPLY` 和 `IGIX_AI_PREFILL_ACK`。模型只输出当前运行时字段描述中的 `code`，字段路径由表单桥接器依据当前元数据解析，不能由模型直接生成。

## 窗口控制协议

助手发送：

```js
{ type: 'IGIX_ASSISTANT_WINDOW', action: 'compact|wide|toggle-wide|fullscreen|toggle-fullscreen|close|get-state|escape' }
```

父页面回传：

```js
{
  type: 'IGIX_ASSISTANT_WINDOW_STATE',
  state: { view: 'compact|wide|fullscreen', isOpen: true, iframeLoaded: true }
}
```

窗口协议的 targetOrigin 优先从 `document.referrer` 推导，无法推导时回退到已知 iGIX origin。接收状态时同时校验 `event.source` 和 `event.origin`。

## 当前用户

`igixUser` 按 `top -> parent -> self` 查找 `gspframeworkService.common.userInfos.get()`，只保留 `userId`、`code`、`name`、`mobilePhone`、组织和租户等白名单字段。当前仅 `name` 用于欢迎语；预填关闭时不会把用户信息写入动作。

## 历史与导出

- localStorage key：`huanbao_current_conversation`、`huanbao_conversation_history`、`huanbao_current_mode`。
- 历史最多 50 条，不保存 loading/streaming 中间态。
- 导出 Word 使用 HTML `.doc`，不引入复杂文档依赖。

## AI Gateway

`ai-gateway/` 是 Java 17 + Spring Boot + PostgreSQL/KingbaseES 兼容服务，提供健康检查、制度问答和办公智能代理、智能问数签名身份与服务端授权、会话映射、人员管理 CRUD、动作校验和查询审计 API。

## 安全边界

- 生产环境必须通过 AI Gateway 隐藏 Dify Key。
- 智能问数只信任 Gateway 验证后的门户身份和服务端 DataScope；浏览器 body 中的用户字段不能覆盖签名身份。
- 父页面必须校验权限并按 `actionId` 幂等消费动作。
- `IGIX_AI_ACTION` 应配置明确 targetOrigin。
- 字段回填必须校验 `requestId`、`formKey`、助手 iframe 和目标表单 iframe 的来源。
- 真实回填必须通过 `BindingData.setValue`，没有 ACK 不得显示成功。
- 不发送自动提交动作。
- localStorage 不能替代服务端审计。
