一、 建设定调：从“全量重构”转向“体验升级与组件治理”

由于后端微服务微内核（huanbao-dataquery）已经稳态运行，涵盖 DomainSemanticProvider、SQL AST 组织注入、只读 KingbaseES、46 项指标语义及 63 家实体厂闭环。前端核心任务已明确为：

  • 定调降维：严禁使用“前端全量重构”这一危险口号，正式定名为《前端体验升级与组件治理方案》，防止代码生成工具对生产链路造成“改退化”；
  • 渐进增强：保留现有的 DataQueryResult.vue、DataQueryChart.vue、dataQueryProtocol.js 和 SSE 管道，在其基础上向上做多分析类型适配与细节打磨；
  • 动态驱动：消灭死板的单一问数模板，改为由后端的 analysisType 动态驱动 Generative UI。

二、 能力架构：四大业务能力 + 两项平台通用支撑

分类 能力名称 生产链路与协议 治理与增强重点
四大业务能力 制度问答 (policy) Gateway 代理 Dify 知识库检索 保留现有 Dify 知识库资产；强化 Markdown 排版与原文来源抽屉，过滤 <think>。
办公智能 (office-ai) Gateway 代理 Master SSE 流式服务 严禁在低代码平台上写死业务逻辑；保障打字机实时流，卡片提供复制、Word 导出。
流程助手 (workflow) 前端卡片 + iGIX postMessage 桥 动态发现菜单；仅 verified 单据展示按钮，补齐父页面 ACK 确认与动作审计落库。
智能问数 (data-query) Gateway 签名身份 + huanbao-dataquery 微服务 扩展 FACT、TREND、RANKING 等多视图；拒绝派生指标前端 AVG；未授权极简阻断。
两项平台支撑 智能自适应 (adaptive) 前端 UI 提示 + Gateway 统一分发 定位为全局路由交互层，消除中心区写死子助手的误导；负责会话上下文平滑流转。
文件支持池 (File Hub) 前端轻量抽取 + Gateway 文档接口 定位为通用附件工具；一期仅服务公文背景提取与表格预览，不直接混入生产指标库。

三、 智能问数 Generative UI 矩阵（彻底解耦单一模板）

拒绝所有问题硬套“近半年累计+最新月+同比+环比”；前端 DataQueryResult.vue 必须按微服务返回的 analysisType 动态渲染对应的视觉呈现：

analysisType 业务场景示例 动态 Generative UI 呈现规范
FACT / DETAIL 秦皇岛8月份发电量是多少 单值 KPI 胶囊 + 当期数据口径说明 + 历史同比/环比标签。不强行画多月折线图。
TREND 查询秦皇岛近半年的全厂发电量 方案 A 模板：近半年累计 + 当期值 + 同环比 KPI；连续折线图；副标题“【周期】【指标】数据要点”（最高、最低、最新环比、走势）。
RANKING 今年项目公司发电量排名 TopN 排名柱状图 + 紧凑排行事实清单（排名、企业名称、数值、占比）+ 导出 CSV。
COMPARISON 秦皇岛与保定8月发电量对比 双主体对标 KPI 组 + 并排柱状对比图 + 差异额与幅度计算。
ANOMALY 秦皇岛近期数据波动异常排查 异常警示卡（⚠ 值得关注）+ 环比异动明细 + 关联指标线索（仅在查得实测值时出现）。
OVERVIEW 集团垃圾焚烧板块经营总览 多板块 KPI 矩阵 + 产能与电量大盘分布 + 经营简报公文块。

四、 跨能力协同：经营分析向办公公文的受控闭环

为满足“查近三个月垃圾入厂量，帮我做一份分析简报”等复合需求，正式确立跨模块协同链路：

协同铁律：问数负责事实，办公负责表达。
1. 统一中枢分流至 composite_data_to_doc；
2. huanbao-dataquery 执行只读查询与统计审计，输出确凿的数据 JSON；
3. 将结构化事实注入 Office AI，生成公文级简报；
4. 前端既挂载 KPI 与趋势图，下方又无缝衔接简报正文，并支持一键导出带图表的正式报告。

七、 流程助手动作回执与审计闭环

消灭“前端 postMessage 发出即代表表单打开”的假闭环漏洞，规范三方握手与审计：

环宝助手 (actionBridge)
   │
   │  1. postMessage(IGIX_AI_ACTION, payload + actionId) [显式 portalOrigin]
   ▼
iGIX 门户父页面
   │
   │  2. 权限校验、openMenu、打开业务表单
   │  3. 回传 postMessage(IGIX_AI_ACTION_ACK, { actionId, status: 'success' | 'failed' })
   ▼
环宝助手
   │
   │  4. 收到 ACK：更新卡片状态为“已在门户中打开”
   │  5. 异步调用 POST /api/ai/action-audits，完成真实落库
