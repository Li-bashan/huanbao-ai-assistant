## 五、后续跨部门领域包通过 DomainSemanticProvider SPI 快速扩展接入指南

后续采购、财务等领域接入时，保持问数微内核的稳定边界，不在前端增加领域判断，也不把领域 SQL 重新塞回 Dify 沙箱。建议按以下契约实施：

1. 新建领域实现类，实现 `DomainSemanticProvider`，声明唯一 `domainCode`，提供领域关键词、指标解析、组织/实体解析、时间表达式和查询策略。
2. 将指标口径写入领域自己的语义 DSL/Provider，明确单位、分子分母、时间粒度、组织粒度和空值规则；所有可执行指标必须关联真实表字段或可审计计算表达式。
3. 通过 Java SPI 在 `META-INF/services/` 注册 Provider，启动时由微内核发现并校验，避免修改 Gateway 的身份、授权和协议代码。
4. 领域 SQL 只能通过统一查询计划和 SQL AST 注入组织授权条件，禁止拼接用户输入，禁止绕过只读数据源和审计链路。
5. 每个领域包至少补齐：指标口径单元测试、组织权限测试、真实库核心场景回归、图表/证据协议断言和 20 并发基线。
6. 发布顺序固定为：领域包构建 → 静态检查与单测 → 测试库回归 → 生产只读连接验证 → 小流量灰度 → 正式签收。领域包不得携带数据库密码、Dify Key 或签名密钥。

采购领域优先接入采购金额、合同执行率、到货及时率和待办逾期；财务领域优先接入收入、成本、利润、回款和预算执行。两个领域都复用现有用户、组织和审计模型，只扩展 DomainSemanticProvider，不复制一套权限系统。
