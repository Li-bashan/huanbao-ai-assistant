# 部署说明

更新时间：2026-09-12

> 本文按当前仓库和线上只读探测更新。部署前必须先确认工作区改动已经提交，并在服务器核对 Gateway 的 Dify Key、数据库连接和前端地址。本文不包含任何密钥。

## 1. 组成

| 组件 | 本地默认 | 说明 |
|---|---:|---|
| Vue/Vite 前端 | 5173 | 构建后为静态文件，可由 Nginx 托管 |
| AI Gateway | 8088 | Spring Boot；线上只读健康地址返回 0.1.0 / UP |
| huanbao-dataquery | 8089 | Spring Boot；只接受 Gateway 内部调用，负责意图、查库和结构化分析 |
| Dify | /v1 | 由 Gateway 服务端调用，浏览器不应读取 Dify Key |
| KingbaseES | 目标环境配置 | 本次未连接、未执行业务 SQL |

当前生产服务器统一为 `121.237.178.23`。前端静态发布目录为 `/opt/huanbao-ai-assistant`，由 `docker-nginx-1` 容器挂载 `dist/` 提供服务；对外入口为 `http://121.237.178.23:9002`，SSH 端口为 `22`，登录用户为 `root`。登录密码不写入仓库，使用服务器凭据或密码管理工具保管。

## 2. 前端

执行 npm ci 和 npm run build。构建产物在 dist/。本次 npm run build 已通过，Vite 报告部分 chunk 超过 500 kB，这是性能优化提示，不是构建失败。若修改 .env.local，必须重启开发服务；生产环境应通过服务器环境变量或构建时配置注入非敏感网关地址。

当前工作区页面链路：

- 制度问答、办公智能：/api/ai/master/chat，代码已提交并与 origin/main 同步；生产服务器部署待确认。
- 智能问数：/api/ai/data-query/access 和 /api/ai/data-query/chat。
- 流程助手：前端动作卡片和门户 postMessage，不调用 Dify。

## 3. Gateway

在 ai-gateway 目录执行 mvn clean test 和 mvn package -DskipTests。

运行时至少需要配置：

- DIFY_POLICY_API_KEY
- DIFY_OFFICE_API_KEY
- DIFY_MASTER_API_KEY
- DIFY_DATA_QUERY_API_KEY
- DATA_QUERY_ADMIN_TOKEN
- DATA_QUERY_IDENTITY_SECRET
- 数据库连接、CORS 来源和 Dify Base URL

密钥只放服务器环境变量或受控配置中心，不写入 Git、文档和浏览器构建产物。Gateway 的 dify.master.api-base 默认是本地示例值，生产必须显式核对。

### 3.1 huanbao-dataquery

在 `huanbao-dataquery` 目录执行 `mvn clean test` 和 `mvn package -DskipTests`。指标字典和组织映射由 Maven 一起打入 Jar，发布前必须确认以下两个条目存在：

- `BOOT-INF/classes/semantic/METRIC_SEMANTIC_DICTIONARY.json`
- `BOOT-INF/classes/semantic/patch_dim_org_mapping.sql`

修改 `docs/METRIC_SEMANTIC_DICTIONARY.json`、意图规则或问数流水线时，必须同步构建并重启线上 `huanbao-dataquery:8089`。只替换前端 `dist/` 或只重载 Nginx 都不算完成，不能让前端推荐问题和旧问数 Jar 跨版本运行。

## 4. 数据库

执行 DDL 前先在测试库核对 schema、权限和已有对象。docs/sql/ 下的四个文件用于：动作审计、问数审计、问数授权和多用户迁移。本次只读检查文件内容，未执行任何 SQL。

上线前至少确认：

- ai_data_query_user 已建表并有经过授权的测试用户；
- ai_data_query_audit、ai_action_audit 和会话映射相关表已建成；
- Dify 业务表、指标字典和组织表的真实字段与工作流 Prompt 一致；
- 数据库账号只有必要的查询权限，并设置查询超时和结果上限。

## 5. Nginx 与发布顺序

建议 Nginx 将前端静态文件指向 dist/，将 /api/ai/ 反向代理到 Gateway 127.0.0.1:8088，并按真实门户来源设置 CORS/iframe 策略。不要用 position: fixed 代替门户嵌入布局，也不要把 Dify API Base 直接暴露为浏览器业务入口。

当前服务器不是该项目的 Git 工作区，正式发布使用 GitLab CI 自动完成。主分支每次提交会先通过前端、Gateway、dataquery 的测试和构建，再通过 SSH 部署密钥发布；任一健康检查失败会恢复本次发布前的前端和两个后端 Jar。

### 5.1 GitLab CI 发布变量

以下变量配置在 GitLab 项目 Settings → CI/CD → Variables 中，密钥和 known_hosts 必须使用 Protected 变量，不得写入仓库：

- `PROD_SSH_PRIVATE_KEY`：生产机部署专用 SSH 私钥；对应公钥放在服务器 `root` 的 `authorized_keys`。
- `PROD_SSH_KNOWN_HOSTS`：由可信管理员生成的 `121.237.178.23` 主机指纹。
- `PROD_DATAQUERY_SERVICE`、`PROD_DATAQUERY_JAR_PATH`：线上 8089 服务的 systemd 单元名和现有 Jar 绝对路径。
- `PROD_GATEWAY_SERVICE`、`PROD_GATEWAY_JAR_PATH`：线上 8088 服务的 systemd 单元名和现有 Jar 绝对路径。

可选变量为 `PROD_SSH_HOST`、`PROD_SSH_USER`、`PROD_SSH_PORT`、`PROD_WEB_ROOT`、`PROD_NGINX_CONTAINER`，默认分别为 `121.237.178.23`、`root`、`22`、`/opt/huanbao-ai-assistant`、`docker-nginx-1`。在没有配置上述部署变量时，发布任务会在任何生产文件发生变化前失败并提示缺项。

发布脚本为 `tools/deploy-production.sh`，它会先做服务、Jar、Nginx 和构建产物预检查，再创建备份，最后重启 8089、8088 和 Nginx 并轮询三个健康地址。生产发布只允许主分支自动执行，并使用 `resource_group: production` 防止并发覆盖。

首次启用前，必须由有权限的管理员核对 `PROD_DATAQUERY_JAR_PATH`、`PROD_GATEWAY_JAR_PATH` 和两个 systemd 服务名；仓库文档没有猜测这两个现场路径。当前机器没有生产 SSH 凭据，因此本次本地修复在配置部署变量前不能直接同步到服务器。

手工应急发布仍按以下顺序执行：

1. 本地确认前端 `npm run build`、Gateway `mvn clean test`、dataquery `mvn clean test` 和真实门户回归均通过。
2. 执行 dataquery 打包并检查 Jar 内的两个 semantic 条目，再按现场既有 systemd/Docker 编排同步并重启 8089。
3. 审核待提交文档改动，确认不包含 Key、HAR 中的敏感内容或临时截图；代码主提交已经与 origin/main 同步。
4. 将 `dist/` 上传到 `/opt/huanbao-ai-assistant/.release-stage-<release-id>`，在服务器执行 `tar -czf backups/dist-<release-id>.tar.gz -C . dist` 留档。
5. 执行 `rsync -a --delete .release-stage-<release-id>/dist/ dist/`，再执行 `docker exec docker-nginx-1 nginx -t && docker exec docker-nginx-1 nginx -s reload`。
6. 重载 Nginx 后先访问 `/api/ai/health`，再用真实门户验证以下问数回归：`查询今年各项目公司垃圾处理量排名，展示前十名`、`查询本月生活垃圾入厂量完成情况，并按项目公司对比`。验收必须是 v2 `analysis_result`，排名结果不超过请求的 Top N，不能只看页面出现了“处理完成”。

## 6. 当前验收边界

线上健康接口已验证；未授权用户接口返回 401；空身份问数返回 CURRENT_USER_MISSING。这些只证明服务入口和基础拦截可用。Dify Key 的实际 App 绑定、Kingbase 实库、生产前端地址、真实门户用户和动作执行回执仍需部署环境验收。
