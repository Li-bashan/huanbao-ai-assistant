## 环境变量

`.env.local` 不提交。`.env.example` 可提交。

```env
VITE_DIFY_USER=your-user-id
VITE_USE_DIFY=true
VITE_POLICY_DIFY_API_BASE=http://your-dify-host/v1
VITE_POLICY_DIFY_API_KEY=replace-with-local-secret
VITE_OFFICE_DIFY_API_BASE=http://your-dify-host/v1
VITE_OFFICE_DIFY_API_KEY=replace-with-local-secret
```

上述变量反映当前前端直连实现，只能放在不提交的 `.env.local`。由于所有 `VITE_` 变量都会进入浏览器构建产物，企业生产部署应尽快切换到 AI Gateway，并将 Dify Key 移到后端环境变量。`VITE_AI_GATEWAY_BASE_URL` 当前尚未被前端代码使用。

## 常见错误排查

- 服务器没有新代码：检查本地是否 `git push`。
- 环境变量不生效：重启 dev 或重新构建。
- 页面缓存：浏览器强刷。
- 确认版本：

```bash
git log --oneline -5
```

- 401：Dify Key 错误。
- Agent blocking 错误：办公智能必须 streaming。
- iGIX 用户服务不可用：独立访问前端时属于预期，只有门户 iframe 环境能读取。
- 窗口按钮点击无变化：确认页面位于门户 iframe，且父页面已监听 `IGIX_ASSISTANT_WINDOW` 并回传状态。
- 表单打开两次：确认 iGIX 父页面按 `payload.actionId` 幂等消费。

## AI Gateway 部署说明

AI Gateway 是新增 Spring Boot 后端服务，目录：

```bash
cd /LBSops/huanbao-ai-assistant/ai-gateway
```

### 运行环境

- Java 17+
- Maven 3.8+
- PostgreSQL

### 数据库初始化

在 PostgreSQL 中执行：

```bash
psql "postgresql://USER:PASSWORD@HOST:5432/huanbao_ai" -f docs/sql/ai_action_audit.sql
```

如果使用环境变量，建议单独准备 PostgreSQL 原生连接串：

```bash
export AI_GATEWAY_PSQL_URL=postgresql://USER:PASSWORD@HOST:5432/huanbao_ai
psql "$AI_GATEWAY_PSQL_URL" -f docs/sql/ai_action_audit.sql
```

### 后端环境变量

```bash
export AI_GATEWAY_PORT=8088
export AI_GATEWAY_DB_URL=jdbc:postgresql://localhost:5432/huanbao_ai
export AI_GATEWAY_DB_USERNAME=postgres
export AI_GATEWAY_DB_PASSWORD=your-password
export DIFY_POLICY_API_BASE=http://your-dify-host/v1
export DIFY_POLICY_API_KEY=replace-with-backend-env-secret
export DIFY_POLICY_TIMEOUT_MS=30000
```

不要把真实 `DIFY_POLICY_API_KEY` 写入代码、文档或 Git 提交记录。

### 本地启动

```bash
cd ~/company-projects/huanbao-ai-assistant/ai-gateway
mvn spring-boot:run
```

```bash
curl http://localhost:8088/api/ai/health
```

### Nginx 反向代理建议

可将 `/api/ai/` 转发到 AI Gateway：

```nginx
location /api/ai/ {
    proxy_pass http://127.0.0.1:8088/api/ai/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```
