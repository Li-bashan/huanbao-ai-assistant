# 门户嵌入说明

更新时间：2026-07-22

## 嵌入形态

环宝 AI 智能助手通过 iframe 嵌入 iGIX 门户右侧区域。助手内部保持 `width: 100%`、`height: 100vh` 的 Header / ChatBody / Footer 结构，不使用全局 `position: fixed` 控制门户级位置。

```html
<iframe
  src="http://192.168.245.138:8090"
  title="环宝 AI 智能助手"
  style="width: 100%; height: 100%; border: 0;"
></iframe>
```

门户负责 iframe 容器尺寸、显示层级、悬浮入口和关闭后的恢复入口。

## 窗口控制协议

助手标题栏通过以下消息请求父页面改变窗口：

```js
window.parent.postMessage({
  type: 'IGIX_ASSISTANT_WINDOW',
  action: 'toggle-wide'
}, parentOrigin)
```

支持动作：

| action | 含义 |
|---|---|
| `compact` | 切换小窗口。 |
| `wide` | 切换中窗口。 |
| `toggle-wide` | 在小窗和中窗之间切换。 |
| `fullscreen` | 切换到全屏。 |
| `toggle-fullscreen` | 进入或退出全屏。 |
| `close` | 关闭助手。 |
| `get-state` | 请求父页面回传当前状态。 |
| `escape` | 处理 Esc，通常由父页面退出全屏或恢复。 |

父页面应回传：

```js
iframe.contentWindow.postMessage({
  type: 'IGIX_ASSISTANT_WINDOW_STATE',
  state: {
    revision: '当前协议版本或状态版本',
    isOpen: true,
    view: 'compact',
    iframeLoaded: true
  }
}, assistantOrigin)
```

`view` 仅允许 `compact`、`wide`、`fullscreen`。助手根据该状态切换图标：中窗显示缩小图标，全屏隐藏中窗/全屏按钮并显示直接返回小窗图标。

助手端优先使用 `document.referrer` 推导 `parentOrigin`，无法推导时回退到 `http://172.17.3.34:5300`。父页面环境如变化，应显式传入正确 origin 或同步更新配置。

## 流程动作协议

用户必须先点击流程卡片确认，助手才发送：

```js
window.parent.postMessage({
  type: 'IGIX_AI_ACTION',
  payload: {
    action: 'open_form',
    formCode: 'CGQSD',
    funcId: '9744034a-7fcc-4510-97fa-f563aecd26e6',
    actionId: '唯一动作标识'
  }
}, '*')
```

普通打开动作的协议要求：

- 消息类型只能使用 `IGIX_AI_ACTION`，不要使用旧的 `HUANBAO_AI_ACTION` 或 `OPEN_FORM`。
- `action` 位于 payload 内，仅允许 `open_form`、`open_menu`。
- 普通打开动作不发送 `fields`，不自动提交；智能字段回填使用下方独立的桥接协议。
- `actionId` 由前端 bridge 自动注入。
- iGIX 父页面必须按 `actionId` 幂等消费，多个监听器不能重复打开同一表单。
- 父页面负责 openMenu、打开表单、点击新增，以及转发已经确认的字段回填请求。
- 发送完成只表示 `postMessage` 已调用；当前助手尚未消费动作执行回执。

生产环境应将动作 targetOrigin 从 `*` 改为明确的门户 origin。

## 表单字段回填桥接协议

原生 `rtcommon / fillform` 只负责展示字段和打开菜单，不能将字段写入真实表单。智能填单必须使用独立的三方握手：

```text
环宝助手
  -> IGIX_AI_PREFILL_REQUEST
门户父页面
  -> openMenu，并保存 requestId 和字段
真实表单桥接器
  -> IGIX_AI_PREFILL_READY
门户父页面
  -> IGIX_AI_PREFILL_APPLY
真实表单桥接器
  -> BindingData.setValue
  -> IGIX_AI_PREFILL_ACK
环宝助手
  -> 根据 ACK 显示已回填或降级
```

助手确认后发送：

```js
window.parent.postMessage({
  type: 'IGIX_AI_PREFILL_REQUEST',
  version: '1.0',
  payload: {
    requestId: '唯一请求标识',
    formKey: 'leave_request',
    fields: [
      { key: 'passportProject', value: '德国出差项目', valueType: 'text' }
    ]
  }
}, portalOrigin)
```

父页面必须按 `formKey` 和字段白名单校验请求，再调用 `gspframeworkService.rtf.func.openMenu`。目标表单通过 ready 后，父页面才可以发送 apply。表单桥接器必须在表单上下文内调用 `frameContext.bindingData.setValue(path, value, true, true)`，然后返回：

```js
{
  type: 'IGIX_AI_PREFILL_ACK',
  version: '1.0',
  requestId: '唯一请求标识',
  status: 'applied',
  appliedFields: ['passportProject'],
  rejectedFields: []
}
```

没有 ACK 不能显示已回填。字段桥接的完整实施方案见 `docs/智能填单表单桥接实施说明.md`。

## iGIX 当前用户读取

助手先按 `window.top`、`window.parent`、`window` 顺序尝试读取：

```js
gspframeworkService.common.userInfos.get()
```

如果助手和门户不是同源，浏览器同源策略会阻止子页面直接读取父页面的 `gspframeworkService`。这不是 CORS 能解决的问题，因为这里不是接口请求，而是跨域读取父窗口对象。此时助手会通过 `postMessage` 请求门户父页面代读用户信息：

```js
// 助手子页面已经内置这一段请求
window.parent.postMessage({
  type: 'IGIX_AI_USER_REQUEST',
  requestId: '本次请求唯一标识'
}, parentOrigin)
```

门户父页面必须在创建 iframe 时注册回执监听。用户信息请求不固定助手 origin，只校验消息确实来自当前助手 iframe，再将回执发回 `event.origin`：

```js
// 这里使用门户组件里实际绑定的助手 iframe 引用
const assistantFrame = this.assistantFrame?.nativeElement

window.addEventListener('message', async (event) => {
  if (event.data?.type !== 'IGIX_AI_USER_REQUEST') return
  if (!assistantFrame || event.source !== assistantFrame.contentWindow) return
  if (!event.source || typeof event.source.postMessage !== 'function') return

  const userInfos = window.gspframeworkService?.common?.userInfos
  let rawUser = null

  try {
    if (typeof userInfos?.get === 'function') {
      rawUser = await Promise.resolve(userInfos.get())
    }
  } catch {
    rawUser = null
  }

  event.source.postMessage({
    type: 'IGIX_AI_USER_RESPONSE',
    requestId: event.data.requestId,
    userInfo: rawUser && {
      userId: rawUser.userId || rawUser.id || '',
      code: rawUser.code || '',
      name: rawUser.name || '',
      mobilePhone: rawUser.mobilePhone || '',
      orgId: rawUser.orgId || '',
      orgName: rawUser.orgName || '',
      unitId: rawUser.unitId || '',
      unitName: rawUser.unitName || '',
      tenantName: rawUser.tenantName || '',
    },
  }, event.origin)
})
```

只保留 `userId`、`code`、`name`、`mobilePhone`、`orgId`、`orgName`、`unitId`、`unitName`、`tenantName`。当前仅姓名用于欢迎语；不写入 localStorage，不读取头像大字段，字段预填关闭时不写入 action payload。

助手会校验回执的 `event.source`、`event.origin` 和 `requestId`，不会接受其他窗口伪造的用户信息。独立访问前端时没有父页面回执，出现 `IGIX CURRENT USER SERVICE NOT FOUND` 或 `IGIX CURRENT USER UNAVAILABLE` 属于预期现象；在门户中仍提示获取不到用户，则说明父页面还没有接入上面的监听器，或者助手 origin 没有加入白名单。

## 父页面职责

- 管理 iframe 小窗、中窗、全屏和关闭状态。
- 回传 `IGIX_ASSISTANT_WINDOW_STATE`。
- 校验消息来源、用户身份和入口权限。
- 按 `actionId` 去重。
- 执行 iGIX 菜单/表单动作并承担操作审计。
- 管理字段回填 pending 请求、目标表单 ready、apply 转发和 ACK 回传。
- 最终提交始终由用户人工确认。

## 联调检查

1. 打开助手后，父页面响应 `get-state`。
2. 小窗、中窗、全屏图标和状态保持一致。
3. Esc、关闭和全屏返回行为符合门户容器设计。
4. 点击一次采购请示单只消费一个 `actionId`，只打开一个表单。
5. 智能填单确认前没有 apply 消息，真实表单回传 ACK 后助手才显示回填状态。
6. 独立访问前端时聊天、历史和导出仍可使用。
