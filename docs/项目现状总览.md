## 1. 一句话结论

项目已经是可演示、可使用的 Vue 3 + Vite 企业门户右侧助手 V1。制度问答、办公智能和智能问数都已接入 Dify，流程助手仍是前端动作卡片试点版。当前智能问数已由 AI Gateway 负责身份、权限、会话归属、Dify 代理、SSE 和审计；Dify 发布版本、KingbaseES 实库和 iGIX 签名身份仍需目标环境验收。

## 5. 当前真实链路

### 制度问答

```text
用户输入
  -> 前端 chatApi.js blocking
  -> Dify 制度问答应用
  -> 公司制度知识库检索
  -> LLM + think 清洗
  -> 引用来源和答案返回前端
```

### 办公智能

```text
用户输入
  -> 前端 chatApi.js Agent streaming
  -> Dify Agent 应用
  -> SSE 增量更新
  -> 前端过滤 <think> 后展示和保存
```

### 智能问数

```text
用户输入
  -> 前端 dataQueryApi.js
  -> Gateway 签名身份和服务端 DataScope
  -> Gateway 会话归属映射
  -> Dify 智能问数应用
  -> 指标字典 / 指标规则检索
  -> Qwen 生成 SQL
  -> SQL 解析校验
  -> rookie_text2data 插件直连 KingbaseES
  -> 失败修复、补查、计算、图表和回答
```

Gateway 通过服务端签名身份和授权表确认用户，再将 Dify 内部会话 ID 保留在服务端映射表中。浏览器只持有用户专属会话句柄，不能直接调用 Dify 或伪造用户身份。

## 6. 前端和 AI Gateway 边界

当前智能问数页面先调用 Gateway access 接口做 UI 状态提示，真正请求仍由 Gateway 再次执行身份和服务端授权校验。`src/config/dataQueryAccess.js` 不再是生产授权点。

当前主要风险：

- Dify 工作流发布版本和 Kingbase 数据源必须在目标环境复核。
- iGIX 必须提供可验证的签名身份；没有签名密钥时不能把 BODY_TRIAL 当作生产认证。
- 智能问数首轮 SQL 节点端口当前存在常量 `54321`，补查节点从 `DB_PORT` 读取，发布前必须确认一致。
- 流程动作当前 `targetOrigin` 仍是 `*`，生产环境应配置门户 origin 白名单。
- 流程父页面还需要按 `actionId` 幂等消费并回传执行结果。
- localStorage 历史不能替代服务端审计。

## 7. 当前开发验收重点

1. `npm run build` 必须通过。
2. 制度问答验证 `差旅费包括哪些费用？`，确认 blocking、引用来源和 `<think>` 清洗。
3. 办公智能验证通知或会议纪要生成，确认 Agent SSE 增量和历史不保存思考内容。
4. 智能问数验证已支持的生产指标问题，确认真实 Dify 返回、失败 SQL 修复和图表输出；同时核对已发布版本与最新草稿的差异。
5. 流程助手验证 `打开采购请示单`，确认只有用户点击卡片后才发送 `IGIX_AI_ACTION`。
6. 在真实 iGIX 门户验收窗口协议、当前用户握手、动作幂等和采购请示单打开。
7. 在真实 iGIX 门户确认签名身份和 Gateway 代理稳定后，再关闭任何仅用于本地开发的 Dify 直连配置。
