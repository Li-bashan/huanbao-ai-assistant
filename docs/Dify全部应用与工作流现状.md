## 4. 当前项目使用的工作流

### 4.1 制度问答：`智慧办公—环宝制度智能助手`

已发布工作流 ID：`6acb5d6d-82cc-455a-b64e-d7dd63c7e0e8`。

节点链路是：

```text
开始
  -> 知识检索
  -> LLM
  -> 代码执行
  -> 直接回复
```

| 节点 ID | 类型 | 名称 | 当前职责 |
|---|---|---|---|
| `1711528914102` | start | 开始 | 接收用户问题 |
| `1711528915811` | knowledge-retrieval | 知识检索 | 检索 `公司制度` 数据集，multiple 检索，`top_k=4`，向量权重 0.7、关键词权重 0.3，启用 `gte-rerank-v2` 重排 |
| `1711528917469` | llm | LLM | 使用 `qwen-122b`，根据知识库上下文生成制度答案；提示词要求只依据 `<context>`，不编造制度内容 |
| `1782885299705` | code | 代码执行 | 清洗 LLM 的 `reasoning_content` 和 `<think>` 内容，输出干净答案 |
| `1711528919501` | answer | 直接回复 | 返回代码节点的最终答案 |

制度知识库：`公司制度`，ID 为 `d594600f-e999-449c-8985-ab139b335358`。当前前端通过 Dify blocking 接收答案和引用来源。

### 4.2 办公智能：Agent 应用，不是 Workflow 图

当前应用是 `智慧办公-环宝办公智能助手`，应用 ID 为 `3368e09c-20fe-4526-beac-70897eacb18e`，模式为 `agent`。数据库中没有与它关联的 `workflow_id`，因此不存在可以按 Workflow 节点表逐个描述的图形工作流。

前端代码按 Agent streaming 接入，重点是 SSE 增量读取和过滤 `<think>`。不要因为 Dify 控制台里能看到 Agent 应用，就在文档里虚构 start、LLM、answer 等 Workflow 节点。

### 4.3 流程助手：不调用 Dify

流程助手由前端 `intentRouter`、`workflowActions.js` 和 iGIX `postMessage` 动作协议实现。当前唯一 `verified` 的入口是采购请示单；它没有 Dify 应用，也没有 Dify 工作流节点。

## 5. 其他已发布工作流

### 5.1 `01-数据库查询助手`：旧版智能问数

已发布工作流 ID：`c7c7e33e-2740-48b9-817e-5c39d5c686f6`，28 个节点、29 条连线，使用 `Qwen3.8-27B`。

它与当前智能问数的共同点是：都通过 `rookie_text2data / rookie_excute_sql` 执行 KingbaseES SQL，都有 SQL 解析、失败修复、补查、计算和图表回答链路，也都没有 AI Gateway HTTP 节点。

它与当前应用的主要差异是：

- 旧版使用两个 SQL 工具节点查询指标字典和指标规则；当前应用改为两个 knowledge-retrieval 节点。
- 旧版因此是 28 / 29，当前应用是 28 / 30。
- 旧版的已发布应用不能作为当前前端 `VITE_DATA_QUERY_DIFY_API_BASE` 的目标，切换前必须确认应用 ID 和 API Key 对应关系。

节点按业务分组如下：

| 分组 | 节点 |
|---|---|
| 输入和 SQL 生成 | 用户问题、查询指标字典、整理指标字典、查询指标规则、整理指标规则、生成指标SQL、解析SQL列表 |
| 首轮执行 | 逐条执行SQL、组装SQL参数、执行SQL查询、整理查询结果 |
| 失败修复 | 提取失败项、是否有失败SQL、修复失败SQL、解析修复SQL |
| 补查和汇总 | 补查执行、组装补查参数、执行补查SQL、整理补查结果、合并查询结果、统一汇总入口 |
| 计算和回答 | 计算引擎、汇总查询结果、生成回答与图表参数、解析图表并生成回复、输出最终回答 |

## 9. 发布和维护要求

1. 任何“最新草稿已完成”的描述，都必须同时写明是否已在 Dify 控制台发布。
2. 变更智能问数节点后，必须同时核对首轮 SQL 工具和补查 SQL 工具的端口、数据库类型、表白名单和失败分支。
3. 如果将 SQL 查询迁移到 AI Gateway，必须新增并验证 Dify HTTP 请求节点，再删除或停用直接 SQL 插件节点；不能只改文档。
4. 上线前要让用户身份进入服务端可信链路，不能把前端 `current_user_name` 作为唯一授权依据。
5. 测试、历史和已删除应用保留在盘点里，但不应被写进当前生产调用链。

智能问数的 28 节点逐节点配置见[《Dify 智能问数工作流现状》](./Dify智能问数工作流现状.md)，项目代码和部署总览见[《项目现状总览》](./项目现状总览.md)。
